# WinOld Recovery — Recovery Recipes (v0.1)

A recipe is the per-application logic for **Detect → Plan → Execute → Verify**, plus the card copy shown to the user. Every recipe obeys the SAFETY_MODEL invariants: it reads the source only through `SafeFs`, writes only what its `Plan()` listed, never overwrites silently, never touches registry hives, never shows or logs secret values.

Conventions used below:

- `OLD` = old profile root inside the source, e.g. `C:\Windows.old\Users\VJ`.
- `NEW` = destination profile root, e.g. `C:\Users\VJ`. `NEW_LOCAL` = `NEW\AppData\Local`, `NEW_ROAMING` = `NEW\AppData\Roaming`.
- `SESSION` = the session folder `%LOCALAPPDATA%\WinOldRecovery\sessions\<stamp>\`; exports go to `SESSION\exports\<recipe>\`.
- "Closed" = the target application has no running process; checked in Preflight and again immediately before Execute.
- Items marked **[verify]** are facts to confirm against the vendor documentation during Milestone 0 or when the recipe is implemented; RESEARCH.md tracks their status.

## R1. Personal folders (file tree)

**Detect.** Profile roots: `<root>\Users\<name>` where the directory contains `NTUSER.DAT` or any of the standard folders; exclude `Default`, `Default User`, `All Users`; `Public` is shown as "Public (shared)". Service accounts (a profile whose `NTUSER.DAT` is absent or whose name matches known service patterns such as `*ServiceAcct`, `MSSQL*`, `defaultuser0`) are shown collapsed under "Other accounts".

Standard folders are located by name in the profile root **and** by reading the old hive `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders` (offline) to catch redirected folders (for example `Documents` moved to `D:\Docs`, which is then outside Windows.old and simply reported as "was redirected to D:\Docs; not in Windows.old"). Known Folder GUID values (`{F42EE2D3-909F-4907-8871-4C22FC0BF756}` Documents, `{0DDD015D-B06C-45D5-8C4C-F59713854639}` Pictures, `{374DE290-123F-4565-9164-39C4925E467B}` Downloads, `{35286A68-3C57-41A1-BBB1-0EAE73D76C95}` Videos, `{A0C69A99-21C8-4671-8703-7934162FCF1D}` Music, `{B4BFCC3A-DB2C-424C-B029-7FE99A87C641}` Desktop, `{4C5C32FF-BB9D-43B0-B5B4-2D72E54EAAA4}` Saved Games) are resolved when present.

Everything else at the profile root is a **custom folder** (Undecided by default). `AppData` is shown but only its subfolders are restorable (I4). Legacy junctions (`Application Data`, `Local Settings`, `My Documents`, `Cookies`, `NetHood`, `PrintHood`, `Recent`, `SendTo`, `Start Menu`, `Templates`, `AppData\Local\Application Data`, `History`, `Temporary Internet Files`) are listed greyed with their targets; on real systems these point at the **live** profile.

**Plan.** `Restore` directories become `CopyTree` items to `NEW\<same relative path>` (or to `NEW\Recovered\<relative path>` when the user selects the "restore into Recovered" policy). Per-file overrides become `CopyFile` items. Regeneratable-badged folders inside a restored tree are included unless the user excludes them with "Restore everything except regeneratable folders" (which sets those nodes to Leave Behind explicitly, visibly).

**Execute.** Copy engine (ARCHITECTURE §6).

**Verify.** L0–L2 as per SAFETY_MODEL §7.

**Card copy.** "Your Desktop, Documents, Downloads, Pictures, Videos, Music and Saved Games from the old installation. Restoring merges them into the same folders of your current account; files that already exist are kept and the restored copy is renamed."

**Regeneratable detection rules (badge only).** Folder names: `node_modules`, `.venv`, `venv`, `env` (only if it contains `pyvenv.cfg`), `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.tox`, `.gradle`, `.m2\repository`, `.nuget\packages`, `.cargo\registry`, `target` (only if a sibling `Cargo.toml` or `pom.xml` exists), `bin`/`obj` (only if a sibling `*.csproj`/`*.sln` exists), `build`/`dist`/`.next`/`.nuxt`/`.parcel-cache`/`.turbo` (only if a sibling `package.json` exists), `.cache`, `AppData\Local\pip\cache`, `AppData\Local\npm-cache`, `AppData\Local\Yarn\Cache`, `AppData\Local\uv\cache`, `AppData\Local\Temp`, `AppData\Local\Package Cache`, `AppData\Local\Microsoft\Windows\INetCache`, browser `Cache`/`Code Cache`/`GPUCache`/`Service Worker\CacheStorage`, `AppData\Local\D3DSCache`, `AppData\Local\NVIDIA\DXCache`, `AppData\Local\CrashDumps`, `.ollama\models` (re-downloadable, large). File rules: `*.iso`, `*.img` > 500 MB, installers in Downloads (`*.exe`, `*.msi`, `*.msix`, `*.appx`) shown as "Installer (re-downloadable)". Every rule carries a one-line "regenerated by …" explanation.

## R2. Chromium browsers: Google Chrome, Microsoft Edge

Applies identically to both (same layout). Paths: `OLD\AppData\Local\Google\Chrome\User Data\` and `OLD\AppData\Local\Microsoft\Edge\User Data\`. Profiles: `Default`, `Profile N`; display names from `Local State` → `profile.info_cache.<dir>.name` and `gaia_name`/`user_name` (email shown as the profile's account, not logged).

### What is and is not recoverable

| Data | File(s) | Recoverable after reinstall | Method |
|---|---|---|---|
| Bookmarks | `<profile>\Bookmarks` (JSON), `Bookmarks.bak` | Yes | Convert JSON → Netscape HTML export; optional direct file copy into a **new** profile when the browser is closed |
| History | `<profile>\History` (SQLite: `urls`, `visits`) | Yes, as data | Export to HTML/CSV; Chromium has no "import history from file" |
| Open tabs / sessions | `<profile>\Sessions\Session_*`, `Tabs_*` (SNSS) | Yes, as URL list | Parse SNSS → "Reopen these tabs" HTML list; optional copy of `Sessions\` into the new profile |
| Extensions | `<profile>\Extensions\<id>\<ver>\manifest.json`; `Secure Preferences` → `extensions.settings` | List only | Extension list with store links (`https://chromewebstore.google.com/detail/<id>`, `https://microsoftedge.microsoft.com/addons/detail/<id>`) |
| Autofill addresses/names | `<profile>\Web Data` (`autofill`, `autofill_profiles`) | Yes | Export CSV; optional copy of `Web Data` into a new profile |
| Local Storage / IndexedDB | `<profile>\Local Storage\leveldb`, `IndexedDB\` | Data only | Optional copy into new profile; low value without cookies |
| Preferences | `<profile>\Preferences` | Partially | Not copied in v0.1 (machine-bound values); a later version may cherry-pick |
| **Secure Preferences** | `<profile>\Secure Preferences` | **Do not copy** | HMACs are keyed to the user SID; copying resets settings ("Some settings were reset") |
| **Passwords** | `<profile>\Login Data`, key in `Local State` (`os_crypt.encrypted_key`, `os_crypt.app_bound_encrypted_key`) | **No** | DPAPI (user) for `v10` blobs, App-Bound Encryption via SYSTEM DPAPI + elevation service for `v20` blobs (Chrome/Edge 127+, July 2024). Unrecoverable after reinstall. Restore via Google/Microsoft account sync. |
| **Cookies** | `<profile>\Network\Cookies` | **No** | Same as passwords |
| **Payment cards** | `Web Data` → `credit_cards` | **No** | Same |

### Detect

- Enumerate profiles; for each read `Bookmarks` (count nodes), `History` (row counts via read-only copy), `Sessions` (parse newest `Session_*`), `Extensions` (ids, names from `manifest.json`, with `__MSG_*__` names resolved from `_locales\<default_locale>\messages.json`), `Local State` version (`Last Version` file / `profile.info_cache`).
- Card facts: profile name, bookmark count, history URL count, open-tab count, extension count, last-used time (`History` mtime), browser version that wrote it.
- Sensitive: `Login Data*`, `Network\Cookies`, `Web Data` (partially), `Local State` (contains wrapped keys).

### Plan (components, each individually decidable)

1. **Bookmarks export** → `SESSION\exports\chrome\<profile>\bookmarks.html` (always offered, default Restore).
2. **Bookmarks into browser** (optional, default Undecided): creates a *new* profile directory `NEW_LOCAL\…\User Data\Profile <next free N>` containing only `Bookmarks` and registers it in `Local State` → `profile.info_cache` with name "<old name> (recovered)". Requires browser closed and an installed browser at least as new as the source (`Last Version` compare; otherwise this component is disabled with a reason). Only `Local State` is modified, via JSON round-trip with a backup `Local State.winold-bak` written first. **[verify]** that Chrome accepts a profile dir with only `Bookmarks` + info_cache entry on all current versions; if not, ship export-only.
3. **History export** → `history.html` + `history.csv` (default Restore; marked personal data).
4. **Open tabs list** → `tabs.html` (default Restore).
5. **Extensions list** → `extensions.html` with store links (default Restore).
6. **Autofill export** → `autofill.csv` (default Undecided; personal data).
7. **Passwords / cookies / cards**: fixed component "Cannot be recovered" with the explanation and the sync alternative. No decision control.

### Execute

- All parsing is done on copies of the source files made into `SESSION\tmp` (so SQLite never creates `-journal`/`-wal` next to the source); SQLite opened with `Mode=ReadOnly;` on the copy.
- SNSS reader: magic `SNSS`, int32 version (1 or 3), then records of `uint16 size, uint8 id, payload`; extract `UpdateTabNavigation` (id 6) pickles for URL/title, `SetSelectedNavigationIndex`, `SetTabWindow`, `TabClosed`/`WindowClosed`; keep the newest navigation per live tab. Chrome's `Tabs_*` files are used when `Session_*` is absent.

### Verify

- Exports exist and are non-empty; bookmarks HTML re-parses to the same count; if the profile transplant option ran, `Local State` parses and contains the new entry and `Bookmarks` hash matches.

### Card copy

"Bookmarks, browsing history, the tabs that were open, and the list of installed extensions. **Saved passwords, cookies and payment cards cannot be recovered**: Chrome and Edge encrypt them with keys that only existed on the old Windows installation. Sign in to your Google account (Chrome) or Microsoft account (Edge) to bring those back from sync, if sync was on."

## R3. Mozilla Firefox

Path: `OLD\AppData\Roaming\Mozilla\Firefox\`; `profiles.ini` (`[ProfileN] Name, IsRelative, Path, Default`) and `installs.ini` / `[Install<hash>]` sections map installations to default profiles. Profiles: `Profiles\<random>.<name>\`. Empty profiles (no `places.sqlite`) are shown but default to Leave Behind.

### What is recoverable (all of it, on Windows → Windows)

| Data | Files | Notes |
|---|---|---|
| Bookmarks + history | `places.sqlite` (+ `favicons.sqlite`); `bookmarkbackups\*.jsonlz4` | |
| Passwords | `logins.json` + `key4.db` (must be copied as a pair); also `logins-backup.json` and, when present, `logins.db` **[verify: newer Firefox versions store logins in `logins.db`; observed on a 2026 profile]** | Protected by the Primary Password, empty by default. If a Primary Password was set, Firefox asks for it; the tool cannot bypass it. |
| Cookies | `cookies.sqlite` | Restores logged-in sessions |
| Form history | `formhistory.sqlite` | |
| Permissions, certs | `permissions.sqlite`, `cert9.db` | |
| Sessions / tabs | `sessionstore.jsonlz4` (clean shutdown), `sessionstore-backups\recovery.jsonlz4`, `previous.jsonlz4` | mozLz4: magic `mozLz40\0`, uint32 LE size, LZ4 block |
| Extensions | `extensions\*.xpi`, `extensions.json`, `addonStartup.json.lz4`, `storage-sync-v2.sqlite` (extension settings) | Copy works; a list with AMO links is also exported |
| Site storage | `storage\` (+ `storage.sqlite`), `webappsstore.sqlite` | |
| Preferences | `prefs.js`, `user.js`, `xulstore.json`, `containers.json`, `handlers.json`, `search.json.mozlz4` | |
| Not copied | `cache2` (in `AppData\Local`), `startupCache`, `*.sqlite-wal/-shm` handled with the DB, `lock`, `parent.lock`, `sessionCheckpoints.json`, `times.json` | Regenerated |

### Plan (components)

1. **Profile transplant (recommended)**: for each selected old profile, create `NEW_ROAMING\Mozilla\Firefox\Profiles\<newrandom>.<oldname>-recovered\`, copy the allow-listed files/folders above (including `-wal`/`-shm` side files if present, since the DB may not be checkpointed), and add a `[ProfileN]` section to the new `profiles.ini` (backup written first). The new profile is **not** made default; the user chooses it in `about:profiles`. Firefox must be closed. **[verify]** whether the newer "profile groups" feature (Firefox 135+ `profiles` directory and `profiles.ini` `StoreID`) changes registration; fall back to instructing the user to use `about:profiles → Create → then copy` if the ini format differs from expectation.
2. **Exports** (always available, default Restore): bookmarks HTML (from `places.sqlite` `moz_bookmarks`/`moz_places`), history CSV/HTML, tabs list (from newest sessionstore file), extensions list.
3. **Passwords** are part of the transplant, shown as "Included (protected by your Primary Password if you set one)". No export of passwords in v0.1.

### Execute / Verify

- Copy via engine (files are small; hashed at L2 because they are sensitive).
- Verify: `profiles.ini` parses and lists the new profile; `places.sqlite` copy opens read-only and `PRAGMA integrity_check` returns `ok`; bookmark count equals the source count; `key4.db` + `logins.json` both present if either was present.

### Card copy

"Everything Firefox knows: bookmarks, history, open tabs, saved passwords, cookies (logins), add-ons and settings. Firefox does not tie passwords to the Windows account, so they come back. If you had set a Primary Password, Firefox will ask for it. Restored as a new profile so nothing in your current Firefox is touched."

## R4. Syncthing

### Detect

Search these locations for a Syncthing home (a directory containing `config.xml` **and** `cert.pem` **and** `key.pem`):

- `OLD\AppData\Local\Syncthing` (the default on Windows; `%APPDATA%\Syncthing` is only used when `LocalAppData` is unset, so treat `OLD\AppData\Roaming\Syncthing` as legacy but still scan it), the "Syncthing Custom Home Path" recorded in SyncTrayzor's own `OLD\AppData\Roaming\SyncTrayzor\config.xml` (SyncTrayzor's default Syncthing home is `%LOCALAPPDATA%\Syncthing`; its own `config.xml` and bundled `syncthing.exe` live in `%APPDATA%\SyncTrayzor` and are not restored, but the EXE's file version is recorded), `<root>\ProgramData\Syncthing` (Bill Stewart's administrative "Syncthing Windows Setup" service install, which runs as the local `SyncthingServiceAcct`), `<root>\Windows\System32\config\systemprofile\AppData\Local\Syncthing` (services running as SYSTEM), and every other profile in the source. The user can also "Add a Syncthing folder…" manually for `--home`/`STHOMEDIR` custom locations.

Real systems have several homes at once (the reference machine had an active SyncTrayzor-managed home in `AppData\Local\Syncthing` and a stale 2024 service-mode home in `ProgramData\Syncthing`, with different certificates). The card therefore lists **instances** with: device ID (derived from `cert.pem`), last activity (mtime of `config.xml`, newest log, index directory), folder count, device count, config version attribute, and marks the newest as "probably active".

Parsed from `config.xml` (XML, DTD/external entities disabled): `<folder id label path type paused>`, `<device id name>`, `<gui>` address, `<options>`. **Secrets in config**: `<gui><apikey>`, `<gui><user>/<password>` hash; these are scrubbed to `***` before anything reaches UI or log.

Device ID derivation: SHA-256 over the DER certificate, base32 (no padding), split into groups with Luhn check characters per the Syncthing device-ID specification (docs.syncthing.net/dev/device-ids). Used only for display and for L3 verification that the restored identity matches.

### Components

| Component | Files | Default | Notes |
|---|---|---|---|
| Identity | `cert.pem`, `key.pem` | Restore | Irreplaceable; other devices trust this ID. `key.pem` is sensitive. |
| Configuration | `config.xml` | Restore, **rewritten** | See remap rules below |
| GUI TLS certificate | `https-cert.pem`, `https-key.pem` | Leave (regenerated) | Only matters for browser trust of the local GUI |
| Index database | `index-v0.14.0.db\` (LevelDB, Syncthing 1.x) or `index-v2\` (SQLite, Syncthing 2.0+) | Fixed: regenerated | Syncthing rebuilds it by rescanning and rehashing. A restored index combined with incomplete data is exactly the case in which missing files are announced as deletions to peers, so it is never restored in v0.1. |
| Logs, `csrftokens.txt`, `syncthing.lock`, panic logs | | Fixed: not restored | |
| Custom GUI assets (`gui\`) | rare | Restore if present | |
| Synced folders themselves | e.g. `OLD\Sync` | Handled in the file tree, badged `[Syncthing folder: <label>]` | The tree badge links to the card |

### Config rewrite rules (Plan shows the diff)

1. Every `<folder>` gets `paused="true"`, so nothing scans or syncs until the user reviews each folder in the Syncthing GUI. The card explains this and shows how to unpause.
2. Folder `path` values (and `<defaults><folder path>`, and absolute `versionsPath` parameters under `<versioning>`) that point inside the old profile (`C:\Users\<old>\…`) are remapped to the destination profile; paths outside the profile (e.g. `D:\Sync`) are left as they are but reported "exists / missing" on the new system. The important safety fact from the Syncthing docs: a folder whose `.stfolder` marker is missing is **stopped** with an error (nothing is deleted), but "once the marker reappears, all changes made to the folder locally will be synced (missing files will be considered deletions)". So the dangerous state is *marker present, data incomplete*. Pausing every folder, restoring folder data (including `.stfolder`, `.stignore`, `.stversions`) before unpausing, and never restoring the index together prevent that state.
3. `<gui>` listen address and API key are kept (the API key is a secret; not shown).
4. Any `<device>` entries are kept; `<defaults>`/`<options>` kept.
5. The config `version` attribute is kept; a newer Syncthing migrates older configs automatically; an **older** Syncthing than the one that wrote the config refuses it ("config file version (N) is newer than supported version (M)"; override flag `--allow-newer-config`). The card shows the source version and the installed version when detectable and recommends installing a Syncthing at least as new as the source. Syncthing 2.x also dropped single-dash long options (`--home`, not `-home`).

### Destination

Default `NEW_LOCAL\Syncthing` (Syncthing's current default), or the home that an already-installed Syncthing/SyncTrayzor on the new system uses if detected (the recipe checks for an existing home and **never overwrites it**; if one exists, the restore goes to `NEW_LOCAL\Syncthing.recovered\` and the card explains how to point Syncthing at it with `-home`, or to swap manually).

### Prerequisites

`syncthing.exe` and `SyncTrayzor.exe` not running; a Syncthing service (if present on the new system) stopped.

### Verify

- `config.xml` at destination parses; device count and folder count equal the source; every folder `paused="true"`.
- Device ID derived from destination `cert.pem` equals the source device ID; `key.pem` hash equals the source.
- Optional: if `syncthing.exe` is installed, `syncthing --home <dest> --device-id` prints the same ID (the option appears in the CLI synopsis; confirm behaviour when implementing).

### Card copy

See UX_SPEC §6 for the full six-question block. Key sentence: "Folders are added paused so nothing syncs or deletes until you have checked the paths."

### Alternative

"Start fresh": Leave Behind everything; the new Syncthing generates a new device ID; the user re-pairs each device and re-shares folders. The card states this plainly.

## R5. SSH

**Detect.** `OLD\.ssh\` with `id_rsa`, `id_ecdsa`, `id_ed25519`, `id_dsa`, any file whose first line is `-----BEGIN … PRIVATE KEY-----` (read only the first 64 bytes), `*.pub`, `config`, `known_hosts`, `known_hosts.old`, `authorized_keys`, `environment`, `rc`. Optional server-side: `<root>\ProgramData\ssh\` (`sshd_config`, `ssh_host_*_key*`, `administrators_authorized_keys`) shown as a separate "OpenSSH Server" component, default Undecided.

**Card facts.** Number of key pairs, key types and public fingerprints (SHA-256 of the public key blob, displayed as `SHA256:…`, never the private key), whether a private key appears unencrypted (`-----BEGIN OPENSSH PRIVATE KEY-----` with `none` cipher, detectable from the header without decrypting: the base64 payload begins with `openssh-key-v1` and the ciphername field is `none`), hosts count in `config`, `known_hosts` line count.

**Plan.** Copy the selected files to `NEW\.ssh\` (created if missing). Existing files are never overwritten: if `NEW\.ssh\config` exists, the old one is written as `config.from-windows-old` and the card says to merge manually; same for `known_hosts`. Keys are copied under their original names unless a name conflict exists, then `<name>.from-windows-old`.

**Execute.** After copying, set ACLs on private keys, `config`, and `authorized_keys` to what Win32-OpenSSH requires (wiki "Security protection of various files in Win32-OpenSSH": private keys and the user's `config` must be owned by the user with no other user having access; SYSTEM and Administrators are tolerated). Implementation: `FileSecurity.SetAccessRuleProtection(true, false)`, remove all rules, add FullControl for the destination user (and optionally SYSTEM), set the owner to the destination user; this is the equivalent of `icacls <file> /inheritance:r /grant:r "<user>:F"` and of Microsoft's `Repair-UserKeyPermission`. Also warn if the source key carried the EFS attribute (unreadable). This is a destination write, allowed.

**Verify.** Files present; hashes match; ACL check: no ACE for `Everyone`, `Users`, `Authenticated Users` on private keys; `ssh -G localhost` exits 0 when `ssh.exe` is present (parses `config`).

**Card copy.** "Your SSH identities and the hosts you have trusted. Private keys are restored with strict permissions, as OpenSSH requires. Keys previously loaded into the Windows ssh-agent are not stored in Windows.old in a usable form; run `ssh-add` again after restoring. If a key has no passphrase, consider adding one."

## R6. Git configuration and repositories

### Configuration

`OLD\.gitconfig`, `OLD\.config\git\config`, `OLD\.config\git\ignore`, `OLD\.gitignore_global` (if referenced). `OLD\.git-credentials` is **sensitive plaintext** (default Undecided, card explains that Git Credential Manager tokens stored in Windows Credential Manager are DPAPI-protected and not recoverable; re-authenticate instead). Restore = copy with no overwrite (existing `.gitconfig` → old written as `.gitconfig.from-windows-old` with a merge hint). Card shows `user.name`, `user.email`, `core.sshCommand`, credential helper; scrubs anything under `[credential]` `username`/tokens and `url.*.insteadOf` values that contain `@`.

### Repositories

**Detect.** During scan, any directory containing a `.git` directory (or a `.git` file for worktrees/submodules, parsed for `gitdir:`) is a repo; nested repos are recorded but the outermost is the card entry. Excluded from repo status analysis: anything under `node_modules`, `.cache`, or a `Regeneratable` folder (still listed, marked "vendored").

**Offline analysis (always, no git.exe needed).** Parse `.git\HEAD`, `refs\heads\*`, `packed-refs`, `config` (remotes with credentials stripped from URLs, `branch.<name>.remote/merge`), `refs\remotes\*`, `logs\HEAD` (last activity), `refs\stash` (stash exists), `index` (exists, mtime). Derived: branch list, current branch, remotes, **local-only branches** (no `branch.<b>.remote` and no `refs/remotes/*/<b>`), stash present, last commit time. Offline mode **cannot** determine uncommitted changes or unpushed commits; those show as "unknown (install Git to analyze)".

**With git.exe on the new system (on-demand "Analyze repositories" button).** Locate `git.exe` via `PATH`, `%ProgramFiles%\Git\cmd\git.exe`, and the Git for Windows install-path registry value. Run, per repo, with environment `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `HOME=<NEW profile>` (so the old `.gitconfig` inside Windows.old is never read), a 60 s timeout, and arguments `--no-optional-locks -c safe.directory=* -c core.fsmonitor=false -c gc.auto=0 -c maintenance.auto=false -C <repo>`:

```
git status --porcelain=v2 --branch --show-stash --untracked-files=all --ignored=no
git for-each-ref --format=%(refname:short)%09%(upstream:short)%09%(upstream:track) refs/heads
git log --branches --not --remotes --format=%H%x09%s
git stash list --format=%gd%x09%s
git worktree list --porcelain
```

Interpretation: uncommitted = any `1`/`2`/`u` lines; untracked = `?` lines; unpushed = non-empty `git log --branches --not --remotes`; local-only = heads without upstream (or `[gone]`); ahead counts from `[ahead N]`; stash count from `# stash N`. `--porcelain=v2` is stable across Git versions. `--no-optional-locks` is the documented way to stop `git status` from writing the refreshed index; the integration suite additionally arms the source watchdog during analysis so that any write under `.git` fails the test, and if Git ever writes despite the flags the recipe must copy the `.git` directory to `SESSION\tmp` first and analyze the copy. `safe.directory=*` (honoured in command scope via `-c`) is required because Windows.old files are owned by a foreign SID and Git 2.35.2+ would otherwise refuse with "dubious ownership". Repositories using the reftable backend (`.git\reftable\`) skip the offline ref parse and rely on git.exe.

**Risk levels shown on the card and as tree badges.**

- `[Git: local-only work]` — uncommitted, untracked, unpushed, stash, or local-only branch present, or analysis unknown. Suggested default **Restore**.
- `[Git: clean, pushed]` — none of the above and at least one remote. Suggested default **Undecided** ("re-clonable, but restoring keeps hooks, ignored files, and local config").
- `[Git: no remote]` — always local-only work by definition. Suggested **Restore**.

Repos are restored as ordinary directories (whole tree, including `.git`), with the `Regeneratable` sub-folders still restorable unless the user excludes them.

**Verify.** L0–L2 on the tree; L3: if git.exe present, `git -C <dest> rev-parse HEAD` equals the source HEAD, `git status --porcelain` equals the source status (same flags).

**Card copy.** "Repositories are listed with what would be lost if they were left behind: changes you never committed, files you never added, commits you never pushed, branches that exist nowhere else. A repository with a remote is not automatically safe to leave."

## R7. WSL (Windows Subsystem for Linux) and Docker Desktop

**Detect.**

1. Old registry (offline): `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss\{GUID}` values `DistributionName`, `BasePath`, `Version` (1 or 2), `DefaultUid`, `Flags`, `PackageFamilyName`; `Lxss\DefaultDistribution`. `BasePath` is mapped from the old drive letters into the source root when it lies under the old `C:\Users\<name>\…`; otherwise reported as an external path.
2. Filesystem: `OLD\AppData\Local\Packages\<PackageFamily>\LocalState\ext4.vhdx` (Store distros), `OLD\AppData\Local\wsl\{GUID}\ext4.vhdx` (newer WSL installs), any `ext4.vhdx` under the profile, `OLD\AppData\Local\Docker\wsl\disk\docker_data.vhdx` and `…\wsl\main\ext4.vhdx` (Docker Desktop), Rancher/Podman equivalents by pattern.
3. WSL 1 distros (`Version=1`) have a `rootfs\` directory instead of a VHDX; they are detected and shown as "WSL 1 distribution: manual migration only" (files carry Linux metadata in NTFS extended attributes that a normal copy loses).

**Card facts.** Distro name, WSL version, VHDX size (allocated vs. file size), default UID, last-modified time, whether it is a Docker Desktop disk (`docker-desktop-data`), whether WSL is installed on the new system (`wsl.exe --version` succeeds; on the reference machine WSL was not yet installed).

**Plan (per distro).**

1. `CopyFile` of the VHDX to a user-chosen location outside Windows.old (default `NEW_LOCAL\wsl\recovered\<DistroName>\ext4.vhdx`; the user can choose another drive since disks are often tens of GB). L2 hash verification is mandatory for VHDX files regardless of size.
2. Registration step (optional component, default Restore when WSL is installed; otherwise disabled with the instruction to run `wsl --install --no-distribution` first and reboot): `wsl.exe --shutdown`, then `wsl.exe --import-in-place <DistroName> <path-to-copied-vhdx>`, which registers an existing ext4 VHDX where it is without another copy (added in WSL 0.58; WSL 2 only; the inbox pre-Store WSL does not support it and is detected because `wsl --version` is not recognised there). The tool never runs this against the file inside Windows.old, because Windows.old will be purged. `wsl --import <Name> <Location> <vhdx> --vhd` is the copying alternative and is used when the user prefers WSL to own the copy.
3. Default user step: after import the default user is root. The tool first reads `/etc/wsl.conf` inside the imported distro (`wsl -d <Distro> -u root cat /etc/wsl.conf`); many Store distros already contain `[user] default=<name>` and nothing more is needed. Otherwise it maps the old `DefaultUid` to a name with `wsl -d <Distro> -u root getent passwd <uid>` and appends `[user]\ndefault=<name>` to `/etc/wsl.conf` (documented for all WSL versions), then `wsl --terminate <Distro>`. `wsl --manage <Distro> --set-default-user <name>` (WSL 2.4.4+) is tried first when available and falls back to the `wsl.conf` edit. Every WSL command is shown to the user before it runs.
4. Docker Desktop disks: copy only (default Undecided; images are re-pullable but named volumes may hold data). The card explains that Docker Desktop must be installed first and that its data disk can be swapped in only while Docker Desktop is stopped, with a link to the manual procedure; no automatic registration in v0.1.

**Prerequisites.** Free space for the VHDX; `wsl.exe` present for registration; a distro with the same name not already registered (else suffix `-recovered`).

**Verify.** VHDX header (`vhdxfile` signature at offset 0) present at destination; size and SHA-256 match; if registered, `wsl.exe -l -v` lists the distro and `wsl -d <Distro> -u root -- true` exits 0.

**Card copy.** "A whole Linux environment: packages, projects, dotfiles, databases. It lives in one virtual disk file. We copy the disk out of Windows.old, verify it byte for byte, then register it with WSL as a new distribution."

## R8. Anki

**Detect.** `OLD\AppData\Roaming\Anki2\` (the base folder), the legacy `OLD\Documents\Anki`, and any `-b <path>` argument found in old Start-menu shortcuts (`OLD\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\*.lnk`, parsed read-only) or an `ANKI_BASE` value in the old hive's `Environment` key. Contents: `prefs21.db` (global preferences and profile list), `addons21\` (add-ons, global), per-profile folders (any directory containing `collection.anki2`), `logs\`.

Per profile: `collection.anki2` (SQLite collection), `collection.anki2-wal` (write-ahead log; may be non-empty if Anki was not closed cleanly), `collection.media\` (media files), `collection.media.db2` (media database, regenerable via Tools → Check Media), `backups\*.colpkg` (automatic backups), `media.trash\` (deleted media, regenerable), `deleted.txt` (log of deleted notes), plus add-on-specific files (`*.db`, `*.sqlite`, folders such as `mindmap_web_data`) which are restored with the profile since they are inside it.

**Card facts.** Profile names, note count and card count (read-only query on a copy of `collection.anki2`; `PRAGMA integrity_check`), media file count, newest backup date and count, add-on count (from `addons21\*\manifest.json` names), collection schema version (`col.ver` / `scm`) to warn if the new Anki is older.

**Components.**

| Component | Default | Notes |
|---|---|---|
| Profile folder (collection + `-wal` + media + `deleted.txt` + add-on data) | Restore | Excludes `collection.media.db2`, `media.trash\` (regenerated). If a `-wal` file is non-empty it **must** be copied with the collection. |
| Backups (`backups\`) | Restore | Small `.colpkg` archives; also lets the user recover via File → Switch Profile → Open Backup if the collection fails to open |
| Add-ons (`addons21\`) | Undecided | Reinstallable from AnkiWeb by code; restoring keeps their config |
| Global prefs (`prefs21.db`) | Leave (suggested) | Contains profile list and window state; restoring it over a new Anki's prefs may point at missing profiles. If the destination `Anki2` has no `prefs21.db`, restore is offered. |

**Plan.** Destination `NEW_ROAMING\Anki2\<ProfileName>\`. If a profile of that name exists, restore as `<ProfileName> (recovered)`. Anki must be closed.

**Verify.** `collection.anki2` copy opens read-only, `PRAGMA integrity_check` = `ok`, note count equals source; media file count equals source (minus `media.trash`); newest backup present.

**Card copy.** "Your decks, cards, review history and media. Restored as a profile that Anki lists at start-up. The media index and trash are rebuilt by Anki. If you use AnkiWeb, syncing after a fresh install also restores everything except add-ons; restoring locally avoids a full re-upload and keeps add-on settings."

Every recipe test runs with the source watchdog armed and asserts that canaries never appear in logs.
