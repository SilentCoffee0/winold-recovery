# WSL disks

WSL 2 distros live in an `ext4.vhdx`. WinOld Recovery copies that file to `AppData\Local\wsl\recovered\<name>\` and checks the `vhdxfile` header. The card records file size, allocated size, last-modified time, and (when the old hive has `Lxss`) the distro name, WSL version, and DefaultUid. It may ask the process runner whether `wsl.exe --version` succeeds on this PC. It never runs `wsl --import-in-place` against Windows.old.

Registration (`wsl --shutdown` then `wsl --import-in-place`) is an optional card component (default Restore when `wsl.exe --version` succeeds). After the VHDX is copied, Restore records those requests through the process runner against the recovered file only, so tests never launch WSL and Windows.old is never the import target. After import the default user is root; the card lists the follow-up commands (`cat /etc/wsl.conf`, `getent passwd <DefaultUid>`, `wsl --manage --set-default-user`, `wsl --terminate`) so they can be shown before anything runs. Those default-user commands are not launched. WSL 1 `rootfs` trees are detected as manual-only: a normal copy drops Linux metadata. Docker Desktop disks are copied only, default Undecided, with no automatic Docker registration.
