# WSL disks

WSL 2 distros live in an `ext4.vhdx`. WinOld Recovery copies that file to `AppData\Local\wsl\recovered\<name>\` and checks the `vhdxfile` header. The card records file size, allocated size, last-modified time, and (when the old hive has `Lxss`) the distro name, WSL version, and DefaultUid. It may ask the process runner whether `wsl.exe --version` succeeds on this PC. It never runs `wsl --import-in-place` against Windows.old.

Registration (`wsl --shutdown` then `wsl --import-in-place`) is an optional card component (default Restore when `wsl.exe --version` succeeds). After the VHDX is copied, Restore records those requests through the process runner against the recovered file only, so tests never launch WSL and Windows.old is never the import target. If `wsl -l -v` already lists the distro name, import uses `<name>-recovered`. A second card component, default Leave Behind, registers with `wsl --import --vhd` into `AppData\Local\wsl\owned\` when you want WSL to own a copy. After import the default user is root. Restore then reads `/etc/wsl.conf`; if `[user] default=` is already set it stops. Otherwise it maps the old `DefaultUid` with `getent passwd`, tries `wsl --manage --set-default-user`, and falls back to appending `/etc/wsl.conf` plus `wsl --terminate`. Linux user names are checked before they are passed to WSL. The card still lists those commands before Restore. Verify then records `wsl -l -v` and `wsl -d <name> -u root -- true` when Registration ran. WSL 1 `rootfs` trees are detected as manual-only: a normal copy drops Linux metadata. Docker Desktop disks are copied only, default Undecided, with no automatic Docker registration.
